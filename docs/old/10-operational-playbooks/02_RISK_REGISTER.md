# LOGOS Engine Risk Register

## Risk 1 — Overengineering

### Description

The project may become too abstract too early.

### Severity

High

### Mitigation

Build the smallest useful V1 focused on app-business.

## Risk 2 — Too Much Documentation, Not Enough Product

### Description

Users may not understand value without a demo.

### Severity

High

### Mitigation

Create example workspaces and terminal demos early.

## Risk 3 — AI Dependency

### Description

If the system depends on AI too early, reliability and privacy suffer.

### Severity

Medium

### Mitigation

Make deterministic core useful without AI.

## Risk 4 — Profile Complexity

### Description

Profiles may become inconsistent or hard to maintain.

### Severity

Medium

### Mitigation

Use schemas, tests, and examples.

## Risk 5 — Weak Open Source Onboarding

### Description

Contributors may not know where to help.

### Severity

Medium

### Mitigation

Create contribution categories and good first issues.

## Risk 6 — Positioning Confusion

### Description

Users may confuse LOGOS Engine with a generic AI startup generator.

### Severity

High

### Mitigation

Emphasize local-first structured documentation and decision registry.

## Risk 7 — Generated Docs Feel Generic

### Description

If documents read like generic LLM output, the product loses value.

### Severity

High

### Mitigation

Ground content in decisions, assumptions, and validation rules.
