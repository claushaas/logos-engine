# Messaging

## Messaging Objective

Messaging should help qualified builders quickly understand what LOGOS Engine does, why it exists, and when to use it, while avoiding claims that are not supported by validation evidence.

The message should feel practical, technical, and grounded.

## Message House

The central message is: clarify before you build.

Supporting messages:

- Turn ambiguous project intent into reviewable decisions.
- Keep documentation local, structured, and repository-native.
- Use AI to propose clarity, not to silently decide for you.
- Generate Markdown, HTML artifacts, and agent packs from reviewed state.
- Know what is decided, assumed, risky, and still unclear.

## Core Message

LOGOS Engine helps builders turn early project ambiguity into structured, reviewable documentation before implementation begins.

## One-liner

Clarify your project before you build it.

## Short Description

LOGOS Engine is a local-first TUI that guides builders through AI-assisted project clarification and generates repository-native documentation from reviewed decisions.

## Long Description

LOGOS Engine helps technical and product-adjacent builders make project intent explicit before execution accelerates. It runs locally from the target repository, asks clarifying questions, proposes structured decisions, assumptions, questions, and risks, then renders canonical Markdown into a configurable documentation root, defaulting to `logos/`. Derived HTML artifacts and agent packs help the same intent travel into other workflows without replacing the structured source of truth.

## Audience Message Variants

For technical founders: LOGOS Engine helps you turn a rough product idea into structured project documentation before you start building.

For indie hackers: use LOGOS Engine to get from scattered idea to clear implementation context without moving your project into a SaaS workspace.

For product-minded engineers: define decisions, assumptions, and risks in the repository before code turns ambiguity into architecture.

For consultants and agencies: create a clearer project baseline before execution, handoff, or proposal work.

## Channel Message Variants

GitHub: local-first TUI for decision-first project documentation.

Launch post: a tool for builders who want clearer intent before faster execution.

Technical essay: AI coding makes clarity more important, not less.

Demo video: from empty repository to structured project docs in one local workflow.

## Objection Responses

"Why not just use ChatGPT?" LOGOS Engine is not only a prompt. It keeps structured state, asks through a repeatable profile, requires review, and renders repository-native artifacts.

"Why not use a template?" Templates help with format. LOGOS Engine helps expose decisions, assumptions, questions, and risks before rendering the documents.

"Is this validated?" Not yet. The product is being validated through early users and controlled launch learning.

"Does it prove my idea is good?" No. It helps clarify the project. Customer, market, and business validation still require external evidence.

## Proof Points

Current proof points are product-level and internal:

- Local execution from the repository.
- Structured profile-driven workflow.
- Canonical Markdown output.
- Configurable documentation root with default `logos/`.
- Derived HTML artifacts and agent packs.
- Deterministic diagnostics separated from AI judgment.

External user proof remains a GTM objective.

## Claim Boundaries

Messaging can describe intended value, workflow, and product behavior. It should avoid proof language unless evidence exists.

Do not present the product as validated, revenue-generating, retention-proven, or guaranteed to improve business outcomes.

## Tone and Voice

The voice should be clear, direct, calm, and technical. It should respect builders' intelligence and avoid hype.

Preferred tone: practical, reflective, precise, and open about uncertainty.

## Message Examples

Example launch line: "LOGOS Engine is a local-first TUI for builders who want clearer project decisions before they start building."

Example README line: "Run LOGOS Engine in your repository to turn rough intent into structured documentation, reviewed decisions, and implementation-ready context."

Example community ask: "I am looking for technical builders who have felt the cost of vague project intent and want to test a local-first clarification workflow."

## Forbidden Claims

Forbidden claims include:

- "Validate your startup idea."
- "Guarantee product-market fit."
- "Build the right product automatically."
- "Replace customer discovery."
- "Generate complete business strategy from AI."
- "Proven to increase retention or revenue."
- "The best tool for all product teams."

## Messaging Risks

The product may sound too abstract, too documentation-heavy, or too similar to generic AI writing. Messaging must stay anchored in the concrete workflow and show actual before/after examples.
